# 按菜配料与真实时间采集

食材模型从「全店共用一个灵材数字」改为「8 种食材分别计数」：每道菜起锅时按配方扣 1–2 种食材，任一不足则该食客流失。食材唯一来源是主界面【采集】：三个采集点（后山药圃 / 山溪浅滩 / 南坡竹林），每点一个槽位；指派一名手头空闲的员工、选该点产出的一种食材，**立刻**到手，员工留下做采集动作、采集点进入 5 分钟冷却，结束后自动归队。产量 = `2 + 机缘 × 0.5`，再乘食材稀有度系数。采购与采买工作整条删除（备货按钮、折扣、自动补货、采买台词与经验），灵石不再能换食材；原「+N 灵材」的奖励改为随机食材。

为什么：统一的灵材让菜单只影响售价与耗时，食材从来不是取舍；按种配料后，采什么、派谁、什么时候派，才真正决定今天能上哪些菜。采集冷却走现实时间，是为了让它成为跨页面、跨营业的长期安排，而不是盯着看的一局内操作——这也是它和营业倒计时的关键区别。保留「灵石买食材」的市集方案被否，否则采集不会成为唯一来源，派人的机会成本也就不成立。

代价：

- 采集冷却直接读 `Date.now()`，是全项目**第二处**允许读系统时间的玩法逻辑（第一处是 ADR-0016 的装饰时钟）；其余计时仍必须走场景时钟。时间戳必须进存档，否则关页面就白等或白嫖。
- 存档结构改变，升 v5，旧存档与 `LS4.` 导出码作废（延续「未上线不做迁移」的约定）。
- 删除采购后灵石少了一个消耗口；金灵根不再对口任何工作（和木、土一样闲置），机缘只剩采集产量一项作用。
- 员工采集期间从营业视图、修炼视图与排班中消失；营业中派走一个人就是实打实的减员，只能派手头空闲的员工，不能中途召回。
- 状态栏不再显示库存，缺料信息集中到菜单页与【仓库】的「食材」页。
