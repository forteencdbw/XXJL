# 跨周目账簿留在本地存档里，迁移用手动导出码

飞升会重置本局，玩家需要跨周目的记录才有重复游玩的动力；换设备/清缓存也需要一条不依赖后端的数据迁移路径。我们决定：

1. **账簿（MetaStats）放进主存档**，而不是单独的 key。它包含累计营业天数/食客/收益、单日最高、本机单日收入前 5、目标达成次数、历史最高境界。飞升、破产写新周目存档时把账簿原样带过去；导出码自然包含它。
2. **只做本机记录，不做全球排行榜**。没有账号体系和后端，伪造一个「全球榜」既不可验证也没有意义；本机单日前 5 + 成就足以提供比较目标。
3. **迁移用手动导出码**：`LS1.` 前缀 + UTF-8 JSON 的 Base64，打烊视图「存档」里复制/粘贴。导入覆盖本机当前进度，导入成功后抑制 beforeunload 写回，避免刚导入就被内存里的旧状态覆盖。
4. **成就只记录、不发奖励**。成就阈值覆盖累计/单日/境界/飞升；发奖励会让玩家为刷成就扭曲经营取舍。

代价：

- 账簿跟主存档绑定，主存档损坏则记录一起丢；导出码是唯一备份。
- 没有云同步和全球排行，无法据此做跨玩家比较或运营数据。
- 导出码是明文 Base64，不是防篡改凭证；它服务于迁移，不服务于竞技公平。

这是 v1 的范围选择，不是临时缺口：如果以后接入账号/后端，账簿结构可以直接作为服务端存档的 payload，导出码可以降级为离线备份。
