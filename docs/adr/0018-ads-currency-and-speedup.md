# 广告与加速之间隔一层仙玉

给倒计时加一个可加速的付费型资源：新增货币**仙玉**，唯一来源是看广告，唯一用途是加速。加速可作用于两处——采集冷却（1 仙玉立刻结束一个采集点的冷却）和营业倒计时（1 仙玉立刻打烊，等价于归零硬停）。两者都要二次确认。广告暂不接真实 SDK：`src/ads.ts` 暴露 `showRewardedAd(): Promise<boolean>`，本期是约 1 秒后返回成功的桩，按钮显示「观看中…」，成功后 +1 仙玉。仙玉进存档并升 v6，破产重开与飞升都保留。

为什么：广告平台会变、频次策略会变，但「看广告 → 得仙玉 → 花仙玉加速」这层规则应当稳定。把广告 SDK 收在一个函数后面，游戏只认货币；以后换 SDK、加每日上限或失败/无填充处理，只改 `ads.ts` 与调用处，不碰倒计时与结算。营业倒计时允许加速，是为了让「等一局跑完」也有付费出口，而不是只有采集。

代价：

- 营业加速把硬停的副作用（清场、未结账客人不计收入、不扣声望）暴露成一个按钮；用二次确认兜住误触，但玩家仍可能在没有意识到时会提前结束一局。
- 营业可以连续被仙玉打完，形成更快的「天数→工资/租金/结算」循环；价格（1 仙玉）、广告奖励（1 仙玉）与两处加速都进 `config.ts`，后续可调。
- 桩函数永远成功、无次数限制，不代表真实广告的填充率与失败路径；接 SDK 时必须补上限与失败提示，不能假设 `showRewardedAd()` 一定 true。
- 存档结构再变一次，升 v6，旧存档与 `LS5.` 导出码作废（延续「未上线不做迁移」）。
- 状态栏新增一个常驻数字；仙玉是付费型资源，破产与飞升都不清零。

状态：「仙玉唯一来源是看广告」已被 ADR-0019 主线任务奖励（`config.ts` 的 `tasks[].reward.jade`）取代。
