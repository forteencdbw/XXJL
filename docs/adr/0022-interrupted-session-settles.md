# 刷新按提前打烊结算，不做离线模拟

营业中也会写存档，存的是**进行时快照** `session: { day, goal, revenue, served, wishes }`（只在 `session === "running"` 时写入，跟随每次结账与开局各存一次）。下次打开时，若快照的 `day` 与存档一致，就把当天的收入与统计恢复回来，把这一局标成**已打烊**，玩家进营业视图即按正常结算流程扣工资、租金、还账，并发当日目标奖励。

为什么：原来营业中不落盘，"刷新＝放弃本局"，玩家已经跑掉的时间连同收入一起消失，与 ADR-0020「不吞已花的时间」冲突。而完整的离线模拟需要把排队、耐心、出菜节奏都在关页期间重放，成本和 bug 面都不小。只恢复收入、照常结算，既保住时间投入，又顺手堵住"带着当日收益跳过工资与还账"的路——工资、租金、还账一分不少。

代价：

- 关页期间的营业不再继续，等价于那一刻提前打烊；未结账的客人不计收入。清场数在恢复后显示为 0，结算单不会写"未结账几位"。
- 只恢复收入与统计，不恢复排队、灶台进度、在场客人与随机事件；这一局的收入已经进账，剩下的是收尾。
- 快照只在开局与每次结账时写入。开局与第一次结账之间的极短窗口内崩溃，会丢掉这之前的一小段（可接受）。
- 存档结构新增可选字段 `session`，**版本不变（v7）**：没有该字段视为准备阶段，旧档照常读。
