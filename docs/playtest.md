## 独立盲测与修复

本轮做了四轮独立盲测（一个是“苛刻的经营管理游戏设计师”，一个是“没看过源码的休闲手机玩家”；两者都被要求实际驱动游戏、不给通用建议）。第一轮修复前分数分别是 **4/10** 和 **3/10**；第二轮两人都给 **5/10**；第三轮 **5.5/10** 与 **6/10**；第四轮（当前版本）两人都给 **6/10**。主要结论与对应修复：

| 盲测指出的问题 | 修复 |
|---|---|
| `addUiButton` 在文字还是空的时候就设了可点区域，视觉按钮很大但只能点中最初几个像素（休闲玩家：开张大吉/左侧导航经常点不中或点错） | 每次 `setText` 后重算 hitArea，并给导航/底部按钮额外 6px、出菜 chip 2px 的可点余量；实测「伙计」按钮视觉 50×30，可点 62×42，点背景边缘也能打开 |
| 招待后看不到客人/订单，以为按钮没生效 | 雅座标签改为 12px 深底卡片，显示「待烹饪 / 客人·想吃X ↓出菜」；入座时桌上方飘订单；烹饪显示剩余秒数；镜头初始右移 60 显示门口，HUD 显示下位倒计时 |
| 首日 5 份库存 vs 目标 6 位，不买就必然失败，且购买入口藏在菜单外 | 默认库存 8；菜单页显示「库存 X」并提供「备货 +5」按钮；真实默认首局 8 位/63 灵石/目标达成 |
| 雇满伙计后玩家变观众；亲自下厨拿不到桌子 | 伙计出菜 **0 修为**、玩家亲自出菜 2 点（命中口味再 +1）；入座后 1.5 秒优先窗口留给玩家；跑堂/灶上/采买可单独暂停自动（工资照付）。实测暂停灶上可 11 位/571 灵石/+45 修为 |
| 最优菜单是只挂最贵一道菜；口味只是锦上添花 | 价格越高、每秒收益越低（4.0 → 2.95/秒）；有想吃的菜却上错只付半价。实测 5 道菜全自动 11 位/148，只挂九转灵参 4 位/152 且流失 3，单菜不再无脑最优 |
| 打烊时把正在烹饪/用膳的客人直接删掉，灵材和收入双损失 | 用膳桌打烊照常结算；已下锅未出餐退回灵材；打烊前来不及做完的菜直接拒绝启动 |
| 第 1 天就能借 200 雇满全部伙计，跳过手动期 | 小借改为第 3 日开放 |
| 忙碌时按钮不置灰、点了没反应 | 忙碌时招待/烹饪/出菜变半透明；无效点击给出「还在入座 / 先招待客人 / 你正忙着 / 来不及了」提示 |
| 每日目标奖励相对当日收入太小，可以无视 | 目标奖励改为「基础灵石 + 当日菜品收入 15%」；实测奖励从 21 到 118 |
| 队列在镜头外，看不到客人 | 营业镜头中心移到 100 露出门口与第一位候客；HUD 显示下一到位秒数；镜头仍可拖到队尾 |
| 第二次盲测：伙计面板整行点不中，「雇」与「关闭」点了没反应 | 未雇佣行改为整行可点 Zone（40–680 全宽），关闭按钮加 14px 命中余量；390×844 下实测点整行最右端（x=620）成功雇迎客/跑堂，点 x=62,y=678 成功关闭 |
| 第二次盲测：点「开张大吉」边缘会静默取消菜单 | 开始按钮加大命中区、「先不打烊」移到 420 右侧；实测点开始按钮下缘（330,1164）菜单保持打开，点中央（150,1140）正常开张 |

| 第四次盲测：菜单写「+12 灵石 + 收入 15%」，结算却 +23，费解 | 菜单和打烊视图统一为「奖励：基础 12 灵石 + 当日收入 15%」，明确 15% 是另加的 |

### 第二次盲测后的修复复测（2026-10-24，本轮）

针对第二次盲测（设计 5/10、休闲 5/10）的高影响问题做完修改后，用 390×844 的真机尺寸重新驱动了以下路径：

- 伙计面板：整行最右侧（x=620，远离按钮文字）仍成功雇佣迎客（320→290）与跑堂（290→250）；点自动开关（510,282）后 `auto.server` 由开变关；点关闭（62,678）后遮罩消失。说明“点按钮却关面板/无反应”不再复现。
- 菜单：点开始按钮下缘（330,1164）不会取消，`gameState` 仍为 `selectingMenu`；点开始按钮中央（150,1140）正常进入 `open`。
- 门口：首位候客的屏幕 x=650（720 宽画布右缘留 70px），耐心条可见；营业镜头中心 100 时雅座与门口同屏。
- 修为浮字：强制一桌“想吃清炒灵蔬”的 2 倍客单价稀客、玩家亲自出菜并结算，得 +4 修为（2 基础 +1 口味 +1 稀客），桌面实际出现「+4 修为」浮字，灵石 250→268（6×2×1.5=18）。
- 单菜经济复测（6 级、跑堂/灶上/迎客全自动、库存 200、60 秒）：五道菜 9 位/139 灵石/命中 2/流失 4；只挂九转灵参 4 位/119 灵石/命中 1/流失 8。单菜在每个客人身上仍更贵（约 29.8 vs 15.4），但慢菜与点名落空让它总收入和接待数都更低，修复前“单菜收入接近 1.9 倍”的结构性问题已不存在。
- 打烊时仍在入座/待烹饪的食客现在计入流失，不再无声消失。

### 第三次盲测（当前版本）与修复

设计师 5.5/10、休闲玩家 6/10。两份报告都肯定了订单卡片、目标奖励、雇工行与口味反向压力；新暴露的问题与处理：

- 0 库存仍能开张（休闲玩家实际卡死在第 2 天）：菜单页现在红字提示并禁用开张，必须备货；直接调用 `startSession` 也会被挡回。复测：库存 0 时开张按钮没有可点区域，点「备货 +5」后（50→45 灵石、0→5 灵材）才可开张。
- 升级后目标显示 52、刷新变 64：每日目标现在作为 `dailyGoal` 快照写进存档。复测同一存档刷新前后都显示 52/12；没有该字段的旧存档才回退到按等级重算（64/16）。
- 门口候客只露半身：队列基准位 390→350、间距 70→52。复测单人屏幕 x≈610（右缘留 110px），两人 610/662 都在画布内；营业镜头中心 100。
- 顶部目标被裁、日志压在世界画面上：目标文本 300px 自动换行；主 HUD 18px、境界/修为 16px、见闻录 18px 且每条截到 34 字；状态栏 104→150，三行记录落在深色底内。
- 雇工回本不透明：未雇佣行补日薪；伙计面板写明灶上不读口味。
- 手机按钮偏小：底栏「开张/招待/烹饪」与左栏导航字号 15→20、内边距加大；采购按钮改为 200×80。390×844 实测底栏与两列导航按钮高 75–76 设计（约 41 CSS px），出菜行每道菜约 36 CSS px，二级页关闭条 80 设计（约 43 CSS px）。

仍然刻意保留、没有改成“惩罚式”设计的两点：
- 全自动产线仍可 0 操作净赚（第三轮实测 8 位/57 灵石，扣日薪 18 净 39），但口味只命中 1/3、修为 0；想拿满价或飞升必须自己下场。把自动线改成亏损会逼所有玩家微操，和“可挂机看店”的定位冲突。
- 首日只有 20 灵石，雇不起最便宜的 30 灵石伙计，默认 8 灵材刚好够目标：第一天是教学局，真正的菜单/雇佣/贷款决策从第 2–3 日展开。这是有意的节奏，不是漏做。

### 第四轮盲测（当前版本）

设计师 6/10、休闲玩家 6/10，两人都能完成第 1 天并进入第 2 天。复核结果：

- 0 库存开张：两人均未复现，按钮灰显且无法进入。
- 目标刷新一致：未复现；第 3 天升 2 级并刷新后仍是「满足 2 位口味」。
- 队列可见性：设计师称第 4 天「排队 2/4」只看到一人。本机复测两名候客在屏幕设计坐标 x=610/662（720 宽画布内），未复现裁切；猜测是第二名还在 0.7 秒入场行走中截图，未再改动。
- 关闭：设计师在第 2/3/5 天多次点不中关闭。本版改成底部整条大按钮后，本机脚本对六个二级页各点一次全部关闭；仍未能在真人手指上复验。
- 按钮大小：设计师量到底栏约 29px 高；本版底栏与两列导航已加到约 41 CSS px、关闭条约 43 CSS px、出菜行约 36 CSS px。左侧导航由 8 个竖排小按钮改成两列四行，行距与命中区都放大。
- 出菜：休闲玩家点「清炒灵蔬」上缘（y=1080）没反应，以为上菜坏了。出菜行已上移放大，本机在 y=1050 与 y=1080 点第一道菜均成功进入玩家烹饪；真机手指仍需复验。
- 首日没有实质决策仍是两人共同意见：20 灵石、8 灵材、目标 6，唯一稳妥解是直接开张。保留为教学局，没有为了“有决策”而调高首日难度。

## 节奏估算

- 真实默认首日：8 位、63 灵石、+21 修为；第一天的客人耐心 ×1.8、第一位 1.6s 到店，目标可达。
- 手动/混合线：每次约 11–14 位、+45–49 修为（亲自出菜 + 口味 + 目标），1000 修为约 20–23 天；按 60s 营业加打烊配置，首次飞升约 35–50 分钟。
- 全自动线：伙计出菜 0 修为，只有目标/事件约 +4–8/天，约 125–250 天才够 1000；这是“只赚灵石”的路线，想飞升必须亲自下厨或暂停灶上。这个取舍是刻意的，不是漏掉的平衡。

## 已知边界

- 这是**本机自动化试玩 + 两次独立盲测（AI 评审）**，没有真人玩家样本、全球排行榜或第三方媒体评测，因此不能据此证明「全世界最好玩」；它证明的是「有一款完整、可复现、经过盲测并针对主要问题迭代过的游戏」。
- 盲测分数是各轮修复前的快照（第一轮 4/10、3/10；第二轮 5/10、5/10；第三轮 5.5/10、6/10）。第三轮设计师的测试中途被仓库 HMR 打断并重跑，前后可能不是同一版本；分数只代表盲测当时看到的东西，不是长期结论。
- 没有云存档/全球排行；跨设备迁移依赖手动 `LS1.` 导出码。
- 音频只验证了乐句结构、开关与不报错，未做人耳听感评估。
- 全自动路线仍可能被部分玩家视为“看广告”；但修为只来自亲自下厨，想推进主线必须操作。
