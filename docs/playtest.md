## 美术与沉浸感（2026-10-24 本轮）

本轮目标换成「第一眼被美术吸引、愿意盯着人物与互动、沉浸修仙」，因此把程序化美术整体重做，而不是继续调数值：

- **首次进入的标题页**：月晕、三层水墨远山、山门、朱印、题字「灵膳楼」与「一炉烟火 · 半盏仙途」，浮尘与呼吸的「推门入座」。流程是 标题 → 形象 → 直接进店（完整规则留在左栏「玩法」，不再强制甩一屏说明书）。
- **纵深背景**：屏幕固定的三层水墨山、山门、漂云与月晕；营业时镜头拖到门外也不会露出空白。
- **酒楼立面重绘**：翘角屋檐、瓦线、木柱横梁、窗棂、红帘、石阶苔痕、门前石径；两盏会轻摆的灯笼；招牌用楷体。
- **内景重绘**：木梁、山水挂画、置物架与酒坛、小挂轴、窗棂、石灶与炊具、门口红帘与暖光；灯笼与灶火常亮。
- **人物重做**：宽袖道袍、发髻/长发、会眨的眼睛、呼吸起伏；按身份带剑（剑修/玩家）、葫芦（丹修/魔道）、长须（长老）、草帽（凡人）、犄角（妖修）、托盘（跑堂）、锅勺（灶上）、酒旗（迎客）。入座与用膳出现碗筷热气，玩家下厨时身周升起灵气微光。
- **日常氛围**：每日开张题头「第 X 日 + 晴/灵雾/落英」；晴=浮尘、灵雾=低雾、落英=飘落花瓣；等菜/用膳/排队/伙计各有一句短台词，两位用膳客人偶尔互相搭话，口味上错会抱怨。**点任一人物**会回一句身份台词（剑修说剑、长老说慧根、魔道嫌天地太小），点按有 14px 拖动阈值，拖镜头不会误触。
- **信息减负**：桌卡只留「想吃什么 / 做哪道 / 入座」，用膳中不再顶卡片，避免遮住人物。

验证：390×844 headless 截图见 `docs/screenshots/title.png`、`gender.png`、`busy-tavern.png`、`night-tavern.png`、`upgrades.png`；本轮无脚本错误。边界：全部是 Phaser 程序化矢量绘制，不是手绘原画；没有真人“第一眼”样本，手机字号仍偏小；音频未在本轮重新评估。

### 美术盲测与两轮修正

第一轮美术盲测（美术总监：第一眼 6 / 人物 3 / 沉浸 4；休闲玩家：6 / 3 / 3）指出的具体问题与处理：

- **画面上下不居中**：外层 flex 与 Phaser CENTER_BOTH 双重居中，canvas 在 844 高里顶部 113px、底部 38px。去掉 #app 的 flex 后实测 canvas y=75，上下各 75px。
- **人物脸被头发盖住**：原发际椭圆只留一条窄脸。改成只盖头顶的发帽、加两侧鬓发与眉毛、放大眼睛；再加上每 2.6 秒随机一个角色的点头小动作、呼吸与眨眼。
- **人物站着用膳**：新增坐姿（收腿、压低、咀嚼起伏），碗筷放在角色前方（depth 21）并冒热气，不再被身体挡住。
- **气泡小、贴边被裁、无尾**：气泡改为 17px、190px 自动换行、按相机边缘 clamp，并加朝向下方的小尾巴；点任一人物仍会用身份台词回应。
- **掌柜与客人同座**：待客位从 x=20 移到门口内侧 x=238，玩家改为走过去而不是瞬移；跑堂领客时点「招待」会提示「跑堂正在领客入座」而不是「门外没客人」。
- **室内空墙、灯不落地**：加后柜与酒坛、三块木牌菜单、门侧木柱、灶/门/灯笼的加色光斑（径向渐变 + ADD），并在门外加竹丛、石灯笼、木栅栏与远处屋脊；删掉一条像红色斜梁的多余门廊。
- **左侧货架被切**：营业镜头中心 100→60，左货架与最左雅座完整入画，门口候客仍在 x≈650。
- **顶部数值/日志压叠、遮罩穿透**：状态栏底 0.55→0.72、高度 150→130，见闻录 3 行→1 行；遮罩 0.92–0.95→0.97；菜单目标行缩短为一行。
- **8 桌拥挤**：桌位从 -175..145 扩到 -230..200、人物 scale 1.12→1.18，桌卡间距变大，最左雅座与左货架完整入画；气泡左右各留 120 设计余量。
- **灰方块按钮**：按钮默认底色改暖木色、文字改米白，出菜行高亮改暖金；关闭条也换成木色金边。
- **开场像说明书**：新档选完形象直接进店；标题页底部只留一行「迎客入座 · 点菜出餐 · 打烊修行」。

## 独立盲测与修复

本轮做了四轮独立盲测（一个是“苛刻的经营管理游戏设计师”，一个是“没看过源码的休闲手机玩家”；两者都被要求实际驱动游戏、不给通用建议）。第一轮修复前分数分别是 **4/10** 和 **3/10**；第二轮两人都给 **5/10**；第三轮 **5.5/10** 与 **6/10**；第四轮（当前版本）两人都给 **6/10**。主要结论与对应修复：

| 盲测指出的问题 | 修复 |
|---|---|
| `addUiButton` 在文字还是空的时候就设了可点区域，视觉按钮很大但只能点中最初几个像素（休闲玩家：开张大吉/左侧导航经常点不中或点错） | 每次 `setText` 后重算 hitArea，并给导航/底部按钮额外 6px、出菜 chip 2px 的可点余量；实测「伙计」按钮视觉 50×30，可点 62×42，点背景边缘也能打开 |
| 招待后看不到客人/订单，以为按钮没生效 | 雅座标签改为 12px 深底卡片，显示「待烹饪 / 客人·想吃X ↓出菜」；入座时桌上方飘订单；烹饪显示剩余秒数；镜头初始右移 60 显示门口，HUD 显示下位倒计时 |
| 首日 5 份库存 vs 目标 6 位，不买就必然失败，且购买入口藏在菜单外 | 默认库存 8；菜单页显示「库存 X」并提供「备货 +5」按钮；真实默认首局 8 位/63 灵石/目标达成 |
| 雇满伙计后玩家变观众；亲自下厨拿不到桌子 | 伙计出菜 **0 修为**、玩家亲自出菜 2 点（命中口味再 +1）；入座后 1.5 秒优先窗口留给玩家；跑堂/灶上/采买可单独暂停自动（工资照付）。实测暂停灶上可 11 位/571 灵石/+45 修为 |
| 最优菜单是只挂最贵一道菜；口味只是锦上添花 | 价格越高、每秒收益越低（4.0 → 2.95/秒）；有想吃的菜却上错只付半价。实测 5 道菜全自动 11 位/148，只挂九转灵参 4 位/152 且流失 3，单菜不再无脑最优 |
| 打烊时把正在烹饪/用膳的客人直接删掉，灵材和收入双损失 | 用膳桌打烊照常结算；已下锅未出餐退回灵材；打烊前来不及做完的菜直接拒绝启动 |

### 第二次盲测后的修复复测（2026-10-24，本轮）

- 菜单：点开始按钮下缘（330,1164）不会取消，`gameState` 仍为 `selectingMenu`；点开始按钮中央（150,1140）正常进入 `open`。

### 第四轮盲测（当前版本）

## 已知边界

- 这是**本机自动化试玩 + 两次独立盲测（AI 评审）**，没有真人玩家样本、全球排行榜或第三方媒体评测，因此不能据此证明「全世界最好玩」；它证明的是「有一款完整、可复现、经过盲测并针对主要问题迭代过的游戏」。
- 盲测分数是各轮修复前的快照（第一轮 4/10、3/10；第二轮 5/10、5/10；第三轮 5.5/10、6/10）。第三轮设计师的测试中途被仓库 HMR 打断并重跑，前后可能不是同一版本；分数只代表盲测当时看到的东西，不是长期结论。
- 没有云存档/全球排行；跨设备迁移依赖手动 `LS1.` 导出码。
- 音频只验证了乐句结构、开关与不报错，未做人耳听感评估。
- 全自动路线仍可能被部分玩家视为“看广告”；但修为只来自亲自下厨，想推进主线必须操作。
